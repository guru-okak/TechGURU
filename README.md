# TechGURU

Учебная система сервисного центра: гостевой сайт и кабинеты клиента, мастера и администратора. Vue 3 + Vite, API Cloudflare Workers, постоянная БД D1 (SQLite). Авторизация и регистрация работают через сервер и БД; клиентские данные не подменяются статическими массивами.

## Требования

Node.js 24 или новее, npm. Для локального запуска аккаунт Cloudflare не нужен. Используйте отдельную папку проекта и два терминала.

## Первый запуск

```sh
npm ci
npm run db:setup
```

Скопируйте `.env.example` в `.env`. Для карты укажите ключ JavaScript API в `VITE_YANDEX_MAPS_API_KEY`, для серверной проверки адресов — `YANDEX_GEOCODER_API_KEY`. Ключи не входят в репозиторий. Без них карта/геокодер недоступны; авторизация и остальные операции не требуют этих ключей.

Терминал 1:

```sh
npm run dev:api
```

Терминал 2:

```sh
npm run dev
```

Открыть http://127.0.0.1:5173 . API — http://127.0.0.1:8787/api/health . Используйте один и тот же адрес сайта во время проверки. После изменения серверного кода перезапустите `dev:api`.

## Функции

- Регистрация, вход, refresh-сессии, выход, смена пароля, проверка прав ролей и владельца заявки, CSRF, ограничение попыток входа.
- Заявки с фотографиями, выезд по Москве или приём в сервисе, собственный календарь, проверка адреса и определение зоны.
- Автоназначение по квалификации, доступности, расписанию и доле дневного лимита; ручной разбор исключений, перенос визита.
- Диагностика, предложения новой сметы через администратора и решение клиента, завершение ремонта, выдача и оценка.
- Запчасти: частичный резерв, выдача, расход, возврат; закупки и однократный приход поставки.
- Пользователи и справочники, расписание, обращения мастеров, уведомления в кабинетах, аудит, поиск, фильтры и отчёты CSV.

## База данных

Восемь миграций в `db/migrations` создают 22 предметные таблицы. Демо-наполнение генерирует `db/seeds/demo.mjs`. Файлы настоящей локальной БД и сессии находятся в `.local`, не публикуются и не нужны для установки: база воспроизводится из миграций и seed. После перезапуска локального API данные сохраняются.

```sh
npm run db:check
npm run check
npm run test:d1
```

`check` выполняет серверную типизацию, интеграционные тесты и сборку. Интеграционные проверки и smoke используют отдельные временные БД. `test:d1` проверяет в том числе сохранность после перезапуска.

## Границы версии

GitHub хранит исходники, но сам по себе не запускает сервер и БД. GitHub Pages не подходит для этого API. Для публикации требуется отдельное развёртывание Workers/D1, настоящий database_id, секреты и production-настройки; текущий wrangler.jsonc предназначен для локального запуска.

Внешняя доставка email/SMS не подключена: email ставится в очередь pending, уведомления кабинетов работают. Онлайн-оплата не подключена. В seed используются учебные данные. Запуск с этими паролями и включёнными локальными диагностическими маршрутами нельзя считать производственным развёртыванием.

Большие наборы в части экранов пока загружаются целиком; серверная пагинация всех списков не реализована. Применены пакетные чтения D1 и наборы данных по экранам. Локальные нагрузочные замеры не являются гарантией времени ответа опубликованного сайта.

## Структура

`src` — интерфейс; `server` — API и репозитории; `shared` — контракты и правила; `db` — миграции и демо-данные; `tests` — проверки; `scripts` — запуск и обслуживание. Технические материалы в `docs` содержат также исторические отчёты разработки; актуальная инструкция запуска — этот README.
