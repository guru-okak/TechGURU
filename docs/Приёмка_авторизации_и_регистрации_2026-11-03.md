# Приёмка авторизации и регистрации — 03.11.2026

## Авторизация: 6 пунктов карточки

| Требование | Результат |
|---|---|
| Валидация полей | Проверены пустые поля, формат email, ограничение длины. Ошибки видны у полей. |
| Сообщения пользователю | Неверные данные показываются постоянным сообщением в форме; успешный вход — уведомлением и переходом. |
| Соответствующий кабинет | Через браузер проверены /client, /master и /admin. Роль приходит от сервера. Неподходящий redirect не переводит пользователя в чужой кабинет. |
| Только пользователи из БД | Несуществующий email и неверный пароль отклонены; отключённый аккаунт также отклоняется сервером. |
| Нельзя войти повторно | /login и /register, включая старый switch=1, возвращают вошедшего пользователя в кабинет. API отклоняет повторный вход/регистрацию с действующей access- или refresh-сессией (409). Новая сессия не создаётся. |
| Выход | Проверен выход клиента, мастера, администратора. Сессия отзывается; закрытые страницы требуют входа. Смена аккаунта сначала выполняет выход. |

## Регистрация: 3 пункта карточки

| Требование | Результат |
|---|---|
| Валидация | Проверены обязательные поля, ФИО, email, телефон, пароль 8–128 символов и совпадение паролей. Некорректные данные не создают пользователя. |
| Сообщения | Ошибки полей и постоянное сообщение о занятом email/телефоне проверены через браузер. Успешная регистрация переводит в кабинет клиента. |
| Запись в БД | Через интерфейс создан аккаунт «Проверка Регистрации», qa.auth.20261103@example.com. После обновления страницы он сохраняется. В изолированной D1 отдельно проверены роль client, хеш пароля и сохранение после перезапуска API. |

## Исправлено

Убран обход страниц входа параметром switch=1. Добавлен серверный запрет повторной авторизации и регистрации для действующей сессии. Исправлены противоречивые подсказки длины пароля, проверка телефона, длины ФИО и полей. Ошибки сервера остаются в форме, а не только во временном toast. Ограничены переходы после входа своей ролью. Удалено неиспользуемое определение роли по тексту email.

## Проверки

- Новый интеграционный тест auth-acceptance — успешно: некорректный ввод, дубли, реальное сохранение и PBKDF2, повторный вход, refresh-only сессия, перезапуск, выход, три роли.
- 16 прежних групп реального D1 — успешно: CSRF, роли, подделанные/истёкшие токены, блокировка аккаунта, ротация и replay refresh, конкурентный refresh, отзыв сессии и ограничение попыток входа.
- Production-сборка Vue и TypeScript сервера — успешно.
- Форма регистрации проверена при ширине 375 px: горизонтального переполнения нет. Проверены формы и действия в браузере.
- Проверочный аккаунт оставлен в локальной рабочей БД для просмотра; заявки от его имени не создавались. Остальные автоматические проверки использовали изолированные БД.
